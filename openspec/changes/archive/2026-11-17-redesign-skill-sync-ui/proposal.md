## Why

当前同步页把待操作内容分散在指标卡、筛选器和 skill 卡片中，冲突决策与执行结果也分处弹窗和卡片；设置与首次配置同样缺少清楚的步骤和信息分区。此次调整将优先呈现用户需要处理的事项，同时保持现有同步 API、后端行为和首次配置状态机不变。

## What Changes

- 将同步页组织为冲突、删除、上传、下载、无法同步和已同步分组；已同步项默认折叠，冲突和删除的选择在行内完成，并能展开查看本地路径及基线/本地/云端 hash。
- 在同步页底部常驻显示将执行的上传、下载、删除数量、commit 预期、未决冲突和删除护栏确认。明确区分可执行动作数与选择跳过的决定数。
- 主应用导航保持在左侧：宽屏显示带文字的紧凑栏，窄屏收为带提示的图标栏；顶栏显示当前 Vault 仓库和分支。
- 将设置改为左侧分区目录与设置行布局；资源限制以 MiB 编辑并换算回原字节值，显示缓存使用量，将断开 GitHub 放入危险区，并折叠展示技术 ID。
- 将首次配置改为带名称的六步轨道和内嵌欢迎页，覆盖当前状态机中的正常、异常和等待状态；保留现有授权、仓库绑定及初始化流程。
- 将新增文案加入现有中英文 i18n；不修改同步后端、请求契约或缓存数据格式。

## Capabilities

### New Capabilities

- `workspace-navigation`: 左侧主导航、Vault 上下文和响应式导航呈现。
- `sync-review-ui`: 同步变更分组、决策、详情和执行摘要。
- `settings-ui`: 设置分区、资源单位输入、缓存用量和危险区呈现。
- `onboarding-ui`: 六步首次配置引导及现有流程状态的页面呈现。

### Modified Capabilities

无。现有同步进度与缓存规范的行为契约不变。

## Impact

- 影响 `src/app/layouts`、`src/modules/sync`、`src/modules/settings`、`src/modules/onboarding` 及中英文 locale 文件。
- 同步请求继续使用现有 `selected_action_ids` 和 `decisions`；前端摘要调整为按实际操作计数，`skip` 只作为决定展示。
- 资源限制仍以整数 bytes 保存；MiB 输入仅在前端转换。无需新增依赖或修改 Rust/Tauri API。
