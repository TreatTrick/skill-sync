## Context

当前主应用由 `AppLayout` 提供左侧可折叠导航和页面标题；同步页已通过 `SyncPlan`、`syncDecisions`、`summarizeSyncSelection` 驱动选择与执行；设置页通过本地表单状态和防抖保存 `AppConfig`；首次配置由 `OnboardingFlow` 管理异步状态机。原型改变的是呈现和前端计数方式，不需要改 Rust/Tauri 同步 API、远端数据格式或缓存格式。

实现应以现有 Svelte 组件、语义 token、`@lucide/svelte`、i18n 和 TanStack Query 为基础。`docs/ui-redesign-prototype.html` 是视觉和交互还原基准：除主导航保留左侧以外，布局、尺寸、间距、颜色、控件及各状态呈现均按原型还原，不沿用旧版大卡片替代。原型控制条和模拟数据不进入产品；实际 API、状态机和错误处理继续保留。视觉验收必须覆盖真实 Svelte 页面，不能仅截图原型。

## Goals / Non-Goals

**Goals:**

- 让同步页先呈现待决策和待执行事项，并在执行前汇总动作、commit 及删除护栏。
- 保持主导航在左侧；为窄窗口保留紧凑图标轨，顶栏显示 Vault 仓库和分支。
- 让设置页可快速定位分区，资源限制以 MiB 编辑但仍以整数 bytes 保存。
- 将首次配置重组为六个命名步骤，并完整呈现现有状态机的所有状态。
- 保留现有同步 API、首次配置 API、缓存行为和错误/恢复流程。

**Non-Goals:**

- 不修改 Rust 同步引擎、请求/响应 schema、GitHub 权限或 Vault 数据格式。
- 不新增依赖，不实现真实扫描数据以外的原型模拟场景。
- 不移除现有搜索、筛选、批量处理、主题、语言、恢复或错误处理能力。

## Decisions

### 保留左侧主导航并缩窄

继续使用 `appRoutes` 和 `uiState.sidebarCollapsed`。宽屏展开宽度调整为紧凑带标签导航，折叠态及窄窗口使用图标轨；图标按钮保留本地化 `aria-label` 和标题提示。顶栏从页面标题栏扩展为 Vault 上下文栏，读取 `AppState.config.remote` 的 owner、repo 和 branch。首次配置仍使用独立页面，不套主应用导航。

选择紧凑左栏而非顶部标签，是为了保留桌面工作区的稳定导航位置；不新建第二套路由配置或导航状态。

### 同步列表复用现有计划和决策

按 `SyncSkillEntry.status` 将真实计划条目分为冲突、删除、上传、下载、无法同步和已同步。复用 `syncStatus.ts` 中的选择/决策语义和 `syncDecisions`；页面布局改为单列行，详情展开后读取现有路径与三方 hash。已同步项默认折叠，搜索或筛选仍能定位条目。

删除与冲突的行内选项继续输出现有 `SyncDecision` 值；简单上传/下载仍通过 `selected_action_ids`。不创建第二个并行决策模型。

### 执行数不包含跳过决定

摘要中的“将执行”只计上传、下载、本地删除和远端删除；`skip` 仅计入跳过决定数，不使“执行同步”在没有实际动作时变为可执行。未决冲突另行显示，并保持其本次默认跳过语义。删除护栏仍由后端最终校验，UI 在异常删除计划下要求底栏勾选确认。

### 设置页面保留现有保存机制

设置分区在桌面端使用左侧锚点目录，在窄窗口改为可横向滚动的目录。资源限制输入将 MiB 转成最接近的整数 byte 后写回现有 `AppConfig`，MiB 只作为显示单位；清空或非有限输入不得写入配置。单文件解压上限仍不得大于单 Skill 解压总上限。其他设置继续使用现有防抖保存。

缓存用量条以当前 bytes / capacity 计算，文本仍显示条目数、已用量和上限。断开 GitHub 继续使用现有确认对话框，技术 ID 放入可折叠详情。

### 首次配置只重组视图

六步轨道依据现有 `progressStep` 分组，步骤内容继续委托现有 `OnboardingFlow` 和 API。所有 `OnboardingStage`（包括 `app_not_configured`、等待、限流、manifest 无效和 Vault 不可用）必须有可达视图；重新配置是现有 query mode，不伪装成新的状态机阶段。首次欢迎内容以内嵌页面呈现，不再依赖欢迎弹窗作为唯一入口。

## Risks / Trade-offs

- [窄栏降低文字可见性] → 保留图标标题提示、无障碍名称和清晰选中态，并在 500px 左右窗口检查导航与内容宽度。
- [多项删除的重复控件增加纵向长度] → 保留批量操作，执行前在底栏按本地/云端分开显示数量，并测试删除护栏场景。
- [MiB 转换可能舍入] → 只在有效用户输入后更新 bytes，换算统一使用 `1024 * 1024`，保存前仍由现有 schema 校验整数和上下限关系。
- [首次配置重组遗漏状态] → 以 `OnboardingStage` 联合类型为覆盖清单，不以原型下拉列表代替真实状态机。

## Migration Plan

纯前端渐进替换，不需数据迁移。按工作区导航、同步页、设置页、首次配置页实施；保留原 API 和状态源。出现回归时可回退对应 Svelte 页面/组件，配置 bytes 和远端数据均不改变。

## Open Questions

无待确认的产品决策。窄窗口、长列表和批量删除的视觉/交互验证纳入实现验收。
